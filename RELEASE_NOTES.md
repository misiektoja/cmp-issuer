# Release notes

All notable changes to this project are documented in this file.

## [0.1.0] - TBD

First development release of cmp-issuer, a vendor-neutral cert-manager external issuer for CMPv2 servers. Point a cert-manager `Certificate` at a `CMPIssuer` or `CMPClusterIssuer` and the certificate is enrolled over CMP and written to the usual TLS Secret, so workloads that already consume cert-manager Secrets need no change. Enrollment works against authorities that queue requests or require manual approval, survives a controller restart and never issues a duplicate certificate. Issuance was verified end to end against Nokia NCM 26.7 and EJBCA Community Edition 9.3.7. Licensed under Apache-2.0.

### Features

* **CMPv2 enrollment through cert-manager** - Adds `CMPIssuer` and `CMPClusterIssuer` at `v1alpha1` in the `certmanager.misiektoja.github.io` API group. Certificates enroll with a PKCS #10 request, the only mode **`initialEnrollment`** accepts, because the alternative requires proof of possession over a private key this issuer never reads. See [enrollment](docs/guide/enrollment.md).
* **Mandatory message protection** - Authenticate every CMP message with **PasswordBasedMac** from a shared reference and secret or with a **certificate signature** from an end-entity certificate and key. Protection is required regardless of transport, so HTTP and HTTPS both authenticate. An HTTP issuer reports a one-time readiness warning about the missing confidentiality. See [message protection](docs/guide/message-protection.md).
* **Enrollment completes even when the CA answers slowly** - Authorities that queue requests or require manual approval are polled until the certificate is ready, bounded by **`maximumDuration`** and **`maximumPolls`**. A controller restart mid-enrollment resumes the same request rather than starting a second one. A restart after issuance returns the certificate already obtained. Watch progress with `kubectl get cmptransactions -A` and diagnose a stalled request with `kubectl describe cmptransaction`. See [transaction recovery](docs/guide/transaction-recovery.md).
* **Renewal reissues through P10CR** - cert-manager renewal was verified against **Nokia NCM 26.7** for both values of **`privateKey.rotationPolicy`**. The controller read no private key in either case. This is **re-enrollment, not CMP Key Update Request**, so it fails against a server whose profile authorizes an identity to enroll only once. See [renewal and KUR](docs/guide/renewal-and-kur.md).
* **Verified against Nokia NCM and EJBCA** - Real `Certificate` resources were issued end to end against **Nokia NCM 26.7** and **EJBCA Community Edition 9.3.7** with both protection mechanisms. Per-server setup notes, including the EJBCA enrollment code behavior that blocks a second enrollment, are in [tested PKIs](docs/interoperability/tested-pkis.md).
* **Three ways to install** - Add the Helm repository at **`https://misiektoja.github.io/cmp-issuer/charts`**, apply the self-contained **`install.yaml`** or unpack the **air-gapped bundle** attached to each release, which carries the manager image as an OCI archive next to the chart. CRDs ship inside the chart so `helm upgrade` updates them. They also **survive `helm uninstall`**, so removing the release cannot delete your issuers and transactions. The chart declares **`kubeVersion: >= 1.31.0-0`** and is listed with full metadata in catalogs such as Artifact Hub. See [installation](docs/installation.md).
* **Chart values for the settings that otherwise block issuance** - **`credentialNamespaces`** creates the RoleBinding each namespace needs for its credential Secrets, so the controller never gains cluster-wide Secret access. **`certManagerApproval`** grants cert-manager's built-in approver permission over this issuer type, without which every `CertificateRequest` waits forever with no visible error. Set **`certManagerApproval.create=false`** when approver-policy decides instead. **`logging.level`**, **`logging.stacktraceLevel`** and **`logging.encoder`** shape controller output without knowing the underlying flag names.
* **`kubectl logs` explains an issuance** - Each completed enrollment writes one **`Issued certificate`** line carrying the subject, serial number, validity window, subject alternative names, key details and issuing CA, so you can answer what was issued without decoding the Secret or reaching the CMP server. A queued enrollment reports each wait and its deadline. A rejection names the typed CMP failure. The log never carries credential values, private keys or CSR bodies.
* **Guided setup and symptom-based troubleshooting** - [Getting started](docs/getting-started.md) goes from an empty cluster to an issued certificate in six steps with the expected output at each one. [Troubleshooting](docs/operations/troubleshooting.md) is organized by the symptom you actually see. Full documentation is under [docs/](docs/).

### Security

* **Workload private keys are never read** - The controller forwards the signed PKCS #10 request from cert-manager and never touches the private key cert-manager generated. See [private-key handling](docs/guide/private-key-handling.md).
* **Namespace-bounded credential access** - The manager ClusterRole carries no Secret access at all. A `CMPIssuer` reads credential and trust Secrets only in namespaces you explicitly grant. A `CMPClusterIssuer` reads them only in the controller's own namespace. See [credential Secret access](docs/operations/secret-access.md).
* **Fail-closed response validation** - CSR signatures, response protection, transaction identifiers, nonces, the issued public key and certificate chains are all verified before a certificate is accepted. A failed transport or a rejected response stores no partial material. Every response must also come from the authority configured as **`spec.protocol.recipient`**, so a subordinate CA under a shared trust anchor cannot substitute an answer. See [CMP response trust](docs/guide/cmp-response-trust.md).
* **Reviewed CMP verification path** - The CMP encoding dependency is pinned to a **reviewed branch** rather than its published release, which accepts a signature-protected response from any certificate chaining to a configured trust anchor without matching the sender the message claims and returns an issued certificate without checking that it certifies the key that was requested. The branch also corrects CMP media type parsing, CMP-over-HTTP error handling and response nonce validation on a delayed delivery, and it bounds the poll interval a server can ask for. The exact version is named in the bill of materials attached to the release. See [ADR 0001](docs/adr/0001-cmp-library.md).
* **Attested, inspectable release artifacts** - Multi-architecture images for **`linux/amd64`** and **`linux/arm64`** are published to the GitHub Container Registry with a build provenance attestation, alongside a **CycloneDX bill of materials** that records a resolved license for every module in the build. Every push and a weekly schedule report vulnerable dependencies, leaked credentials and container image findings. See [provenance](docs/provenance.md).

### Known limitations

The API group is served at `v1alpha1` and may change. Renewal reissues through P10CR rather than CMP Key Update Request. Transaction state persistence has documented gaps. See [known limitations](docs/known-limitations.md) before relying on this release in production.
